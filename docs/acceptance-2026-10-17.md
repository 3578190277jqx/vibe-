# 整体验收与修复记录

日期：2026-10-17。范围：前五步及当前本地启动流程。第 6 步仍为「等素材，暂不启用」。

## 检查结论

本地功能回归通过，并修复了检查中复现的问题。现有程序化开场、七章摄像机路径、文字窗口、产品模型、品牌默认文案和留资接口契约继续沿用；没有接入视频、修改用户数据库或执行生产部署。

| 复现的问题 | 修复 |
| --- | --- |
| 帧时间以秒累计，却与 27 毫秒比较，降档无法触发 | 新增 world-runtime.js，完整 90 帧按毫秒判断；测量使用原始帧间隔，模拟仍使用上限 0.06 秒 |
| 降低 DPR 后粒子 uPixel 保持旧值 | 降到 DPR 1 时同步画布、后期处理和粒子 uniform |
| 手机页脚隐藏 FPS，也隐藏了降档提示 | 降档后明确显示「已自动降档」 |
| 回到标签页将后台时间计入动画，开场可能直接结束 | 隐藏时暂停渲染，返回时丢弃时钟增量且保留动画相位；开场计时扣除后台停留 |
| 桌面减少动态效果未覆盖全部 CSS 过渡和延迟 | 全部过渡压缩为 0.01ms，并清除延迟 |
| 辉光基线额外叠加 0.04 | 恢复桌面 0.46、手机 0.34，点击脉冲保留 |
| 无 WebGL 时七章默认文字叠在一起 | 保留中文错误提示及首章文字，隐藏其余章节和不可用导航 |
| 启动说明允许不满足项目要求的 Node 22 | 统一为 Node.js 24 或更高 |
| 配置生成命令可覆盖已有 .env | 已存在时拒绝覆盖，保留配置 |
| 文档建议删库更新文案，会丢失留资 | 改为按 key 原地更新 site_content，附实际可执行示例 |

## 已执行验证

- `npm test`：36 项通过，包括新增帧率守护边界、90 帧窗口、后台时钟相位与前端模块可访问性。
- 真实 PostgreSQL 18.4：八项场景通过，含外层计数为 9；覆盖并发限流、去重、额度保留、TTL、CMS、RLS 和 HTTP 契约。
- 桌面与 375px 浏览器：实际触发降档，确认 DPR 为 1、粒子参数同步及页脚提示；模拟两分钟后台增量，返回时动画时间不跳变。
- 故障注入：禁用 WebGL 后出现中文提示且仅保留一章；后期处理初始化抛错后直接渲染仍正常，可跳转到最后一章。
- 七章场景：锚点、交叉溶解、指示器、三个产品完整入镜、独立旋转、重播与顶栏跳转通过。
- 移动视口：375×812、375×667、375×568、375×400 和 812×375；桌面 1440×900。检查底部排版、44px 圆点触摸区域、全宽表单、文字滚动和真实留资。
- 表单：桌面与手机实际新增/重复、422、429、蜜罐、断网、503、非 JSON 及 10 秒超时重试通过。
- CMS：开场不等待请求、刷新获取数据库修改、纯文本安全、字段兜底、接口失败及 5 秒超时通过。
- 干净副本：不安装 node_modules，按启动说明创建配置、初始化、启动并访问真实 HTTP；重复创建配置不覆盖；按文档更新标题后，已收集邮箱仍可去重。
- 独立只读审查完成，确认上述修复后未发现新的可确认缺陷。

## 验证边界

浏览器移动视口与故障注入不等同于实体安卓、iOS 或微信内置浏览器实测，也不作为稳定 30 FPS 的证明。生产托管、数据库账号权限、国内公网可达性及 ICP 上线前置仍按既有待定部署流程处理。
