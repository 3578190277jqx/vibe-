# 第 5 步：移动端体验

`mobile.css` 在主样式后加载，仅在不超过 860px 的视口生效。保持原有三维场景、系统字体、品牌配色和 HTML 文案。原第六章表单在新增产品章后位于第七章，仍按稳定 key `portal` 提交。

## 文字与底部导航

- 七章文字沿底部排布，左右通常为 20px 留白，底部为导航预留 104px；同时计算刘海和底部安全区。
- 标题、正文、标签和反馈保留文字阴影，适当提高手机正文对比度，没有给章节加遮罩。
- 右侧横线导航改为底部七个小圆点，视觉尺寸 6px，当前章节为 8px；每个按钮的触摸区域为 44×44px，保留 aria-label、aria-current 和键盘焦点样式。
- 矮屏、横屏或较长 CMS 文案可在当前文字区域内滚动；切到其他章节后复位。文字外的区域仍可滚动世界时间轴。
- 页脚位于圆点下方，安全区由 env(safe-area-inset-*) 计算。手机减少动态效果时压缩 CSS 过渡并取消延迟。

## 全宽表单

Portal 邮箱及提交按钮各自占一行，铺满文字栏，最小高度为 48px。邮箱字号为 16px，避免 iOS 常见的聚焦自动放大。反馈在按钮下方保留空间；原有真实提交、错误重试、蜜罐和去重逻辑继续生效。

## 粒子预算

| 类型 | 优化前手机 | 当前手机 | 桌面 |
| --- | ---: | ---: | ---: |
| 星尘 | 1500 | 800 | 4200 |
| 近景浮尘 | 420 | 180 | 1100 |
| 门户星环 | 120 | 72 | 260 |
| 合计 | 2040 | 1052 | 5560 |

手机三类粒子减少约 48%。仍沿用移动端无抗锯齿、DPR 上限 1.5 和 8×8 群集；桌面原数量及 DPR 上限 1.75 保持原样。窄屏识别阈值与 CSS 对齐为 860px，画质在初始化时选择。

第 5 步没有改写帧率守护；后续整体验收已修复其时间单位、粒子 DPR 同步和手机降档提示，详见 `docs/acceptance-2026-10-17.md`。仍未宣称已达到真实安卓 30 FPS；帧率、软键盘和 Safari 安全区需在最终目标设备上验收。

## 文件与检查

新增的 `mobile.css` 必须随静态资源部署，`index.html` 已引用，Node 白名单及 HTTP 测试已放行 CSS。无需编译、打包或额外依赖。

375px 下使用真实 Chrome 的移动视口、触摸输入及 2 倍设备像素比检查，覆盖多种屏高、七章跳转、文字与导航位置、全宽表单和实际入库；另检查横屏及桌面，记录见 `docs/backend-verification.md`。这些属于浏览器模拟验收，不替代实体手机性能或原生软键盘验证。
